# Glossary

Terminology lookup. For deeper material on each concept, follow the cross-links.

| Term | Meaning |
|---|---|
| **Weave** | A repoweave workspace: any directory containing `projects/` (and typically cloned member repos, `.rwv-active`, and symlinked ecosystem workspace files). |
| **Weave root** | The top-level directory of a weave (or workweave), where `.rwv-active` (or `.rwv-workweave`), `projects/`, `<registry>/<owner>/<repo>/`, and surfaced ecosystem symlinks live. |
| **Primary weave** | The main weave at the weave root (as opposed to a workweave under `.workweaves/`). Named `primary` where a verb takes a workspace, as in `rwv sync primary` and `rwv sync-to primary`. |
| **Workweave** | A worktree-based derivative of a weave, created on demand for isolation (agents, features, PR review). Lives at `<parent>/.workweaves/<project>--<name>/` by default. Created, duplicated, and destroyed with `rwv workweave <project> create` (`--from <source>` forks from an existing workweave) and `rwv workweave <project> delete`. |
| **Project** | A directory under `projects/` containing `rwv.toml`, `rwv.lock`, and project-scoped docs. Itself a git repo with normal history. |
| **Project repo** | The git repo at `projects/<name>/`. Carries the manifest, lock, and cross-cutting docs. Does not contain importable code. |
| **Member repo** | A repo listed in a project's `rwv.toml`. Lives at `<registry>/<owner>/<repo>/` as a regular clone in the primary weave and as a git worktree in each workweave. |
| **Canonical clone** (or **Canonical store**) | The full git clone at `<primary>/<registry>/<owner>/<repo>/` (or `<primary>/projects/<name>/`) whose `.git` object store backs both the primary weave checkout and every workweave's git worktree. See [clone-topology](../explanation/joints/clone-topology.md). |
| **Ephemeral branch** | The flat per-workweave git branch (`<project>--<workweave>`, with `/` in scoped project names encoded as `+`) created in each member and project repo when a workweave is created, and deleted when the workweave is deleted or retired. See [workweave-hierarchy](../explanation/joints/workweave-hierarchy.md). |
| **Manifest** (`rwv.toml`) | Declares which repos belong to a project, their roles, and integration config. See [formats](./formats.md). |
| **Lock file** (`rwv.lock`) | Pins repos to exact 40-character commit SHAs for reproducibility. Derived state — output of `rwv lock`, `rwv update`, and `rwv sync` Phase 3. See [lock-as-derived](../explanation/joints/lock-as-derived.md). |
| **Stale lock** | Freshness condition: the lock covers every member repo but pins a revision behind current HEAD. Doctor finding kind `stale-lock`; bypassed with `--allow-stale-lock`. Fixed by `rwv lock`. Contrast **Incomplete lock**. |
| **Incomplete lock** | Coverage condition: the lock has no entry for some member repo. Doctor finding kind `incomplete-lock`; also what `rwv fetch --frozen` refuses on. Fixed by `rwv lock` (adds the missing entry). Contrast **Stale lock**. |
| **Activation** | Selecting the active project (writing `.rwv-active`), surfacing weave-root symlinks, running integration install hooks (`--no-materialize` skips hooks), and verifying integration files in `projects/<name>/`. Performed by `rwv activate <project>`, and by `rwv init` and the `rwv fetch` that activates a project; it does not rewrite integration workspace files to pick up `rwv.toml` changes. Inside a workweave, where `activate` is refused, `rwv materialize` runs hooks and repairs symlinks. |
| **Materialization** | Making the ecosystem state the project's membership and pins imply real on disk, without selecting a project: cleaning up artifacts from disabled integrations, repairing weave-root symlinks, settling drifted attested generated files (`--regenerate-drifted`, `--adopt-drifted`), fitting host settings, and running integration install hooks (`npm install`, `pnpm install`, `uv sync`, `cargo fetch`). Performed by `rwv materialize`; the install hooks alone also run in activation and in `rwv workweave create`. `rwv sync` runs none of it. |
| **Active project** | The project named in `.rwv-active`. Single source of truth in the primary weave — no CWD override. |
| **Authoring verb** | A verb that writes the rwv-owned regions of ecosystem workspace files in `projects/<name>/` from `rwv.toml`: `add`, `remove`, `update` and `role`, which change project composition, and `rwv doctor --fix` as a repair. `rwv init <name>` writes a new project's first set. Every other verb (`activate`, `materialize`, `fetch`, `workweave create`, `init --adopt`, `lock`) does not rewrite integration workspace files to pick up `rwv.toml` changes: the ones that activate or materialize a project surface weave-root symlinks, run install hooks and report a missing or drifted file as a warning, and `lock` does none of that. Inside a workweave the authoring verbs run no install hooks. See the [file-ownership](../explanation/joints/file-ownership.md) trigger model. |
| **Hybrid file** | An ecosystem config file in `projects/<name>/` (such as `Cargo.toml`, `package.json`, `pyproject.toml`, `go.work`, `<name>.code-workspace`) where `rwv` owns specific keys or sections, marked as its own (`[workspace]`, `workspaces`, the `use` block), while the user owns the rest of the document. Contrasts with **fully rwv-owned** files, which rwv writes and deletes whole: the gita CSVs, and the lock files ecosystem tools generate during install hooks (`Cargo.lock`, `package-lock.json`), whose accepted content rwv records in `.rwv-owned-digests`. See [file-ownership](../explanation/joints/file-ownership.md). |
| **Role** | A repo's relationship to a project: `owned`, `fork`, `dependency`, `reference`. Encodes change resistance. See [roles](./roles.md). |
| **Integration** | A built-in unit, shipped with rwv, that translates between repoweave's multi-repo model and one ecosystem's workspace format. Bound by a file-ownership contract (surfacing + content ownership). See [integrations](./integrations/index.md) and [file-ownership](../explanation/joints/file-ownership.md). |
| **Plugin** | An external `rwv-<verb>` executable on `$PATH`, dispatched when a verb isn't built into rwv itself. Must not write rwv-owned files; nothing enforces that at dispatch, and `rwv doctor` notices some violations after the fact. Contrast with **Integration**. See [plugin-protocol](./plugin-protocol.md) and [plugin-boundary](../explanation/joints/plugin-boundary.md). |
| **Bundled plugin** | A plugin that ships with `rwv` in every release channel, installed beside the `rwv` binary by the install script, the release archives, Homebrew, `pip`/`uv` and `cargo install --git` alike, such as `rwv-each` ([rwv each](./rwv-each.md)). It is dispatched, addressed and constrained exactly as any other **Plugin**: it learns the checkout from the envelope and the repos from `rwv status --json`, and does not link `rwv`'s internals. |
| **Registry** | The first segment of a repo's canonical path; a short name for where the repo lives. Built-in: `github`, `gitlab`, `bitbucket`, plus `local`, reachable only as an `rwv add --new` creation address rather than by matching a URL. See [formats — Directory layout](./formats.md#directory-layout). |
| **Canonical tip** | The vetted cross-repo state of a project on a given branch (encoded by that branch's `rwv.lock`). |
| **Lens** | A motivational way of looking at rwv targeted at one audience. Three lenses: [workspace](../explanation/lenses/workspace.md), [monorepo](../explanation/lenses/monorepo.md), [agent](../explanation/lenses/agent.md). |
| **Joint** | A cross-cutting concept that all lenses reference (Diátaxis-explanation, audience-neutral). See [explanation/index.md](../explanation/index.md). |
| **Phase 1'** | First runtime phase of `rwv sync`: replay CWD's unique project commits onto source's project tip, with `rwv.lock` excluded. Its manifest decides which member checkouts replay adds and prunes. |
| **Phase 2** | Second runtime phase of `rwv sync`: advance member repos to the source's lock targets. |
| **Phase 3** | Third runtime phase of `rwv sync`: regenerate `rwv.lock` from post-Phase-2 manifest tips. |
| **Strategy** | Sync strategy (`ff` or `rebase`), applied uniformly across project and member repos. Defaults to `ff` on `rwv sync` (absorbing state into CWD) and `rebase` on `rwv sync-to` (landing a workweave into its parent). (`merge` is not offered — see [sync semantics](../explanation/joints/sync-semantics.md#why-no-merge-strategy).) |
| **Retire** | `rwv sync-to --retire` — post-sync-to cleanup that deletes the workweave on success. The `--retire` flag lives on `rwv sync-to` (the landing direction), not `rwv sync`. |
| **Parent (of a workweave)** | The workspace the workweave was forked from. Recorded in `.rwv-workweave`'s `parent` field. Bare `rwv sync-to` (no target) auto-targets the parent. |
| **sync-to** | `rwv sync-to [<target>]` — the landing verb. Advances a named target to CWD's tip via a three-step orchestration: (1) rebase CWD against target, (2) auto-relock CWD, (3) FF-advance target. Bare invocation inside a workweave auto-targets the recorded parent. Contrast with `rwv sync <source>`, which absorbs state into CWD. See [sync semantics](../explanation/joints/sync-semantics.md). |
| **Selector** | The shared `--role` / `--repo` flag surface on `fetch`, `update`, `push`, `status`. See [reference/cli — Selector grammar](./cli.md#selector-grammar). |
| **Savepoint** | A git ref at `refs/rwv/pre-op/<op-id>` snapshotting a repo's pre-op tip (`refs/rwv/pre-op/<op-id>-target` for a repo in a `sync-to`'s target workspace). Used by `rwv abort` to roll back. |
| **Op-state** | The on-disk record of an in-flight `rwv sync` or `rwv sync-to` operation. Comprises an owner record (`.rwv-op`) at the initiating workspace and zero or more thin leases (`.rwv-op-lease`) at other mutated workspaces. Preserved on phase failure; cleared on success or after `rwv abort`. See [formats](./formats.md#rwv-op--owner-op-state-record). |
| **Owner record** | The full op-state record (`.rwv-op`) written at the initiating workspace. Holds all op parameters, the current phase, converged tips, and named overrides. The sole copy of mutable op state — leases at other workspaces point back to it. See [formats](./formats.md#rwv-op--owner-op-state-record). |
| **Owner workspace** | The workspace that holds the owner record for a given op — the workspace from which `rwv sync` or `rwv sync-to` was invoked. `rwv abort` and `--continue` invoked from a non-owner workspace follow the lease pointer to find it; `rwv abort` rolls back both workspaces from either one. |
| **Lease** | A thin immutable file (`.rwv-op-lease`) written at every workspace an op mutates other than the owner. Provides mutex semantics (prevents concurrent ops) and a pointer to the owner workspace. See [formats](./formats.md#rwv-op-lease--thin-lease-pointer). |
| **`--json` envelope** | The shape `{"$schema": "...", "<key>": [...]}` emitted by JSON-capable verbs, the same whatever `-j` is. Key is verb-specific. See [reference/cli — JSON envelope convention](./cli.md#--json-envelope-convention). |
| **Drift (index / working-tree)** | A repo's index or on-disk files don't match its HEAD tree — e.g. when a branch ref checked out in a workspace is moved externally without updating that workspace's index and working tree. See [shared-refs-drift](../explanation/joints/shared-refs-drift.md). |
| **Replay exclusion** | The mechanism that drops `rwv.lock` from Phase 1' commit diffs: for git, the `rwv.lock merge=rwv-ours` line in the project repo's `.gitattributes`, with the `merge.rwv-ours` driver configured. Doctor reports a missing one as `missing-replay-exclusion` and `missing-merge-driver-config`. See [vcs-as-seam](../explanation/joints/vcs-as-seam.md). |
| **Container** | The directory new workweaves of a project are created in, recorded per project in `projects/<name>/.rwv-workweave-index`. Defaults to `<parent-of-primary>/.workweaves`; `rwv workweave <project> set-container <path>` records another, and `create --dir <path>` overrides it for one workweave. |
| **Surfacing** | Linking a file that lives in `projects/<name>/` to the weave root, where ecosystem tools look for it (`Cargo.toml -> projects/<name>/Cargo.toml`). Surfaced links belong to rwv, and the file they point at to whoever authored it. Doctor reports a link out of step as `surfacing`. See [symlinks-as-structure](../explanation/joints/symlinks-as-structure.md). |
| **Attest** | Record the digest of a generated file's accepted content, with the digests of the inputs it was derived from, in `.rwv-owned-digests`. An attested file whose bytes later differ is reported as `managed-file-drift` and is not regenerated over without consent; one whose inputs moved is `derived-state-stale`. |
| **Ownership receipt** | A recorded claim that rwv created one exact ref in one exact store, kept in `.rwv-workweave-index`. rwv deletes or moves a ref only against a receipt, never because its name looks like one of rwv's. See [doctor findings — vocabulary](./doctor-findings.md#vocabulary-used-throughout). |
| **Consent flag** | A flag that permits one named consequence a verb otherwise refuses, such as `--discard-uncommitted`, `--adopt-drifted` or `--abandon-foreign-tip <repo>`. Each names the loss it accepts; there is no blanket override. See [destructive operations](../explanation/destructive-operations.md). |
